Evaluating the Accuracy, Latency, and Energy-Efficiency Trade-offs of YOLO Deployment on the NVIDIA Jetson Orin Nano

Master's Project Research Guideline

1. Project Focus

Your original idea is strong, but it should be narrowed into a controlled edge-AI benchmarking project. Rather than studying the broad problem of “accuracy versus efficiency in computer vision,” you will compare a small number of YOLO deployment configurations on one NVIDIA Jetson Orin Nano and evaluate them using a clearly defined real-world scenario.

Main research question:
How do model size and TensorRT optimization affect the accuracy, inference speed, and energy efficiency of YOLO object detection on an NVIDIA Jetson Orin Nano?

Supporting questions:

  1. How does YOLO model size affect detection accuracy and inference latency on the Jetson Orin Nano?
  2. How much performance improvement does TensorRT FP16 optimization provide compared with the original PyTorch model?
  3. What trade-off exists among detection accuracy, inference speed, and power consumption for real-time edge deployment?

4. Select One Real-World Application

Choose one application only. Good options include:

  • Indoor person and common-object detection
  • Parking-lot vehicle detection
  • Pedestrian detection
  • Classroom occupancy detection
  • Laboratory equipment detection

A simple indoor object-detection scenario is recommended because common classes such as person, chair, bottle, backpack, and laptop already exist in standard datasets.

Avoid turning this into an autonomous-driving or multi-sensor project. Your application is mainly the test environment for evaluating edge inference performance.

5. Decide Whether You Need Custom Training

Start with pretrained YOLO models. If your chosen object classes already exist in COCO, you probably do not need to train a model from scratch.

If you need custom classes, use transfer learning later. The main research contribution should remain deployment, optimization, and performance evaluation under embedded hardware constraints.

13. Export the Nano Model to TensorRT FP16

Export the same YOLO Nano model to a TensorRT engine using FP16 precision. A typical Ultralytics workflow looks like:

model.export(
    format="engine",
    half=True,
    imgsz=640

Verify the exact export options using the documentation for the installed Ultralytics version.

Build or validate the TensorRT engine on the target Jetson whenever possible.

16. Measure Power and Energy

Collect at least:

  • Average device power
  • Peak device power
  • GPU utilization
  • CPU utilization
  • Memory utilization
  • GPU temperature
  • CPU temperature

Energy per Inference

Calculate:

E = P × t

E = energy per inference
P = average power in watts
t = inference time in seconds

Example:

Power = 12 W
Inference time = 0.020 s

Energy per inference
= 12 × 0.020
= 0.24 joules

18. Warm Up the Model

Do not record benchmark results immediately after model loading. Run approximately 100–200 warm-up inferences before measurement.

This reduces the influence of startup costs such as CUDA initialization, memory allocation, and kernel caching.

19. Repeat Every Benchmark

Do not benchmark a configuration only once.

A reasonable procedure is:

Warm-up = 100 frames

Measured run = 1,000 frames

Number of repeated runs = 5

This gives approximately 5,000 measured inferences per configuration.

20. Record Latency Distributions

Report more than average latency. Include:

  • Mean
  • Median
  • Standard deviation
  • Minimum
  • Maximum
  • P95 latency

P95 latency is useful because a system may have a fast average but still experience occasional slow frames.

21. Measure Both Inference FPS and End-to-End FPS

For pure model inference:

FPS = 1 / latency in seconds

Example:

Latency = 0.025 seconds

FPS = 1 / 0.025
FPS = 40

Report both:

  • Model inference FPS — neural-network processing only
  • End-to-end FPS — camera capture, preprocessing, inference, postprocessing, and output

22. Define "Real Time" Before Testing

Create an explicit definition before conducting the experiment. For example:

For this project, real-time performance is defined as sustained end-to-end processing of at least 30 FPS.

Then classify each configuration objectively as meeting or not meeting the real-time requirement.

26. Quantify TensorRT Improvement

Speedup

Speedup = PyTorch latency / TensorRT latency

Example:

TensorRT latency = 20 ms

Speedup = 40 / 20
Speedup = 2.0×

Also report the percentage change in power and the difference in mAP between PyTorch and TensorRT.

32. Optional Extension: INT8

Only after the main four experiments are complete, you may compare the best FP16 configuration with an INT8 TensorRT version.

  • FPS improvement
  • Power change
  • Energy per inference

33. Scope Boundaries

To keep this project achievable, do not:

  • Compare many different YOLO generations
  • Train a new YOLO architecture from scratch
  • Design a new object-detection architecture
  • Compare Jetson with Raspberry Pi, desktop GPUs, phones, and cloud platforms
  • Evaluate many unrelated optimization frameworks
  • Test multiple unrelated real-world applications
  • Add object tracking unless it is essential
  • Add DeepStream before TensorRT deployment is complete
  • Make INT8 mandatory
  • Use only a displayed FPS value as the performance evaluation

36. Recommended Project Description

This project will experimentally evaluate the trade-offs among detection accuracy, inference latency, and energy efficiency when deploying two sizes of a YOLO object detection model on an NVIDIA Jetson Orin Nano. PyTorch FP32 inference will be compared with TensorRT FP16 optimization under a controlled hardware configuration. Performance will be evaluated using both benchmark data and a small real-world application dataset. The study will measure precision, recall, mAP, latency, FPS, power consumption, and energy per inference to determine which configuration provides the most appropriate balance between accuracy and computational efficiency for real-time edge deployment.

37. Final Goal

By the end of the project, you should be able to answer a clear engineering question:

Which YOLO deployment configuration provides the best practical balance of detection accuracy, real-time performance, and energy efficiency on the NVIDIA Jetson Orin Nano for the selected real-world application?

Your final report should answer this question using reproducible experimental evidence rather than anecdotal observations.

Evaluating Anomaly Detection Methods for Authentication Logs: A Comparison of HBOS, Isolation Forest, and Autoencoders

HBOS · Isolation Forest · Autoencoder
Step-by-step guidance for a 14-week master’s research project.

THE THREE SELECTED TOOLS

One library. Three different approaches.

Use PyOD implementations of HBOS, Isolation Forest, and Autoencoder. All three use the same training and scoring interface. The first is a statistical baseline, the second a tree-based method, and the third a neural network.

Updated research question

How do statistical, tree-based, and neural anomaly detectors compare on future authentication logs under a fixed daily alert budget?

This comparison uses numerical behavioral features. It replaces the earlier event-order research direction: a tabular autoencoder does not explicitly model event sequences.

1. Install the environment

Use a Python version supported by your selected PyOD and PyTorch releases. In Windows PowerShell, run:

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install pyod torch pandas numpy scikit-learn matplotlib jupyterlab
.\.venv\Scripts\python.exe -m pip freeze > requirements-lock.txt
.\.venv\Scripts\python.exe -m jupyterlab

Keep the version record with the project. Start on the CPU and a small dataset; a GPU is optional. Follow the package installation documentation if your Python version is incompatible.

2. Obtain and inspect the data

Download auth.txt.gz and redteam.txt.gz from LANL’s dataset page. Authentication data is large (approximately 7.2 GB compressed), so read in chunks. Start with consecutive days for a pilot; audit the full time coverage before choosing final periods.

Retain timestamps, source user, destination computer, and success/failure. Handle missing fields and document the distinction between human and machine accounts. Match the red-team records using their documented time, user, source computer, and destination computer fields; record ambiguous and unmatched cases.

Known red-team records are confirmed positives. Other records are unlabeled, not proven benign. Never select only attacked users for the main evaluation.

3. Build one shared feature table

Choose one row per user per non-overlapping one-hour window. Score the window after it ends. Aggregate:

  • Authentication count.
  • Failure proportion.
  • Number of distinct destination computers.
  • Number of destinations not previously seen for that user.
  • Mean gap between consecutive authentication events within the window.

For destination novelty, use only history preceding the window. Represent undefined gaps as missing and impute using the training set. Preserve time, user, and known-red-team status as metadata, not model inputs. Mark a window positive if it contains a matched known red-team event.

Output: a feature table, a metadata table, and documented aggregation rules. Keep all observations for a user/window together.

4. Freeze chronological splits

Use earlier complete days for training, subsequent days for validation, and later days for final testing. An approximate 60/20/20 allocation by time is a starting point, not a requirement. Audit positive coverage, then freeze the boundaries before comparing models. Do not randomly shuffle records across splits.

For the main study, train on uncurated historical data and disclose possible contamination. If you exclude known attacks, report that as a separate label-assisted setting. Fit imputation and scaling on training data only.

5. Run all three detectors

The following is a starter template, not an executed experiment. It assumes train_df, validation_df, and test_df are already prepared with the five numeric columns below. Start with each detector’s defaults and record them.

import numpy as np
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from pyod.models.hbos import HBOS
from pyod.models.iforest import IForest
from pyod.models.auto_encoder import AutoEncoder

features = ["auth_count", "failure_ratio", "unique_destinations",
            "new_destinations", "mean_gap_seconds"]

prep = make_pipeline(SimpleImputer(strategy="median"),
                     StandardScaler())
X_train = prep.fit_transform(train_df[features])
X_val = prep.transform(validation_df[features])
X_test = prep.transform(test_df[features])

models = {
    "HBOS": HBOS(),
    "Isolation Forest": IForest(random_state=42),
    "Autoencoder": AutoEncoder(random_state=42),
}

scores = {}
for name, model in models.items():
    model.fit(X_train)
    scores[name] = {
        "validation": model.decision_function(X_val),
        "test": model.decision_function(X_test),
    }
    assert np.isfinite(scores[name]["test"]).all()

Check that each feature has observed training values and resolve infinities before fitting. All three PyOD score outputs use higher values for greater abnormality. Compare within-model rankings; raw scores are not on a common scale. Autoencoder may also perform internal preprocessing: record its settings.

6. Compare equal alert budgets

Predefine budgets such as 10, 25, and 50 user-window alerts per day; adjust these once during planning to suit the selected population. For each model and test day, rank windows by descending score and retain the top K. Apply one deterministic tie rule across all models.

Known-positive window recall at K = selected known-positive windows ÷ all known-positive windows. Aggregate numerator and denominator across test days; days with no positives have undefined daily recall. Record total alerts as well. This is retrospective daily triage: ranking a whole day is not an immediate real-time detector.

Compare training time, scoring throughput, and memory on the same hardware. Include autoencoder preprocessing and device settings. With partial LANL labels, unmatched alerts are unlabeled; do not call them verified false positives. Do not use default contamination-based binary predictions as the main comparison.

7. Tune only on validation data

After a default-settings pilot, use a small predefined search: HBOS histogram bins, Isolation Forest tree/sample settings, and Autoencoder hidden-layer size or training duration. Set a comparable maximum trial count and report compute spent. Choose using validation recall at the primary alert budget. Lock configurations before inspecting final test performance.

Repeat stochastic models with three seeds, such as 11, 22, and 33. HBOS is deterministic for fixed data/settings and does not need redundant seed runs. Save scores, parameters, split dates, and runtime for every experiment.

8. Add one research-depth experiment

Choose temporal degradation: retain the fitted models and compare detection on successive test weeks with the same alert budget. Do not retrain in this experiment. Report positive counts and behavioral changes for each period; changing attack composition can also explain changes in recall.

Inspect a small, consistently selected sample of detected positives, missed positives, and high-scoring unlabeled windows. Explain where the models disagree. Do not claim that an anomalous window is necessarily malicious.

10. Deliver evidence, not a predetermined winner

Deliver a literature-supported question, three reproducible detector runs, a fair alert-budget comparison, a temporal analysis, and a discussion of limitations. Include a results table with recall at each budget, training time, scoring throughput, and variation across seeds/time periods.

A simpler method winning is a valid research result. The contribution is explaining effectiveness, stability, and cost under a defensible protocol.

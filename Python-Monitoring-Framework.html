Design and Evaluation of a Python-Based Cybersecurity Monitoring Framework Using Network Traffic and Host Telemetry

A practical blueprint for building an isolated cybersecurity testbed, generating controlled benign and malicious activity, collecting network and host telemetry, and preparing reproducible datasets for Python-based research.

Recommended Overall Approach

For a master's project, the environment should support a clear research question, a controlled experimental setup, reproducible data collection, and measurable evaluation. A practical design is a small isolated virtual network containing an attack machine, one or more targets, and a dedicated sensor/analysis machine.

2. Set Up the Python Environment

On the Ubuntu sensor VM:

sudo apt update
sudo apt install python3 python3-pip python3-venv git tcpdump

Create a dedicated virtual environment:

python3 -m venv cyber-project
source cyber-project/bin/activate

Install useful analysis packages:

pip install pandas numpy matplotlib scikit-learn
pip install scapy
pip install pyshark
pip install jupyterlab

For machine-learning projects:

pip install xgboost shap

Record dependencies for reproducibility:

pip freeze > requirements.txt

3. Collect Network Data

One of the easiest approaches is PCAP collection. On the sensor:

sudo tcpdump -i eth0 -w data/raw/session01.pcap

The student can rotate files by size or time instead of creating one very large capture.

Python can later read packet captures using Scapy:

from scapy.all import rdpcap

packets = rdpcap("data/raw/session01.pcap")

print("Packets:", len(packets))

for packet in packets[:10]:
    print(packet.summary())

PyShark can also be used when Wireshark-style protocol parsing is useful.

4. Collect Host Data

A stronger master's project collects host logs in addition to packets.

Linux Sources

/var/log/auth.log
/var/log/syslog
/var/log/apache2/access.log
/var/log/apache2/error.log

These can provide events such as successful and failed SSH authentication, sudo activity, HTTP requests, response codes, and system events.

Windows Sources

Windows Security Event Log
PowerShell logs
System logs
Application logs

For richer endpoint telemetry, install Sysmon. It can provide process creation, network connections, file creation, registry modification, and DNS-query events.

6. Generate Controlled Malicious Activity

Run only controlled experiments from Kali against the isolated lab targets. Appropriate academic examples include:

Port scanning
SSH password-guessing simulation
Web directory enumeration
Repeated failed authentication
SQL injection against an intentionally vulnerable web application
Suspicious PowerShell execution
Abnormal file-access behavior
Reconnaissance

For web experiments, use an intentionally vulnerable application such as OWASP Juice Shop instead of testing real websites.

Record each experiment in a ground-truth log:

8. Use Both Lab-Generated and Public Data

For a stronger master's project, use both controlled lab-generated data and a recognized public cybersecurity dataset.

Dataset A → controlled lab-generated data
Dataset B → recognized public cybersecurity dataset

Depending on the research question, examples include CICIDS-style intrusion datasets, UNSW-NB15, or IoT/network-security datasets.

This allows cross-dataset validation:

Train(public) → Test(lab)

Train(lab) → Test(public)

This helps determine whether the method generalizes beyond the student's own testbed.

The most important distinction at master's level is that data collection itself should be treated as part of the research methodology. The thesis should document exactly what generated each event, when it occurred, how it was captured, how it was labeled, which features were extracted, and how leakage between training and testing data was prevented.

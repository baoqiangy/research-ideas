Evaluating Cybersecurity Risk Prioritization Using Qualitative and Quantitative Risk Assessment Methods in a Simulated Organization

The core research question could be:

How does the choice of qualitative versus semi-quantitative cybersecurity risk assessment affect the prioritization of cybersecurity risks?

This is much more manageable.

You do not need access to a real company. You can create a realistic hypothetical organization—for example:

A 100–200 employee healthcare clinic or small business with:

  • Active Directory
  • employee laptops
  • Microsoft 365/email
  • Wi-Fi
  • web server
  • database server
  • VPN
  • cloud storage
  • backup system
  • firewall
  • remote employees
  • third-party vendors

Then create perhaps 12–20 realistic cybersecurity risk scenarios.

Phase 1 — Define the Organization

First create a fictional organization and document its environment.

I would limit it to around:

  • 100–200 users
  • 10–15 important assets
  • 12–20 risks
  • 5–8 major security controls

Do not try to model an entire enterprise.

You should create an asset inventory such as:

AssetFunctionSensitivityCriticality
Patient/customer databaseStores recordsHighCritical
Active DirectoryAuthenticationHighCritical
Email systemCommunicationMediumHigh
Web serverPublic websiteMediumMedium
Backup serverRecoveryHighCritical

This becomes the foundation for everything else.

Phase 2 — Establish the NIST Framework

Use NIST CSF 2.0 as the governance framework rather than trying to use several frameworks simultaneously.

You can map the organization against:

Govern → Identify → Protect → Detect → Respond → Recover.

You can create a simplified Current Profile.

CSF AreaCurrent Condition
GV.RM – Risk ManagementInformal
ID.AM – Asset ManagementPartial inventory
PR.AA – Identity ManagementMFA only for admins
PR.PS – Platform SecurityIrregular patching
DE.CM – Continuous MonitoringLimited
RC.RP – Recovery PlanningBackups exist but rarely tested

Then create a Target Profile showing what the organization should eventually achieve.

That gives the GRC part of the project a clear role instead of allowing GRC to become the entire project.

Phase 3 — Identify Threats and Vulnerabilities

You should identify realistic threat scenarios for each asset.

For instance:

Threat actor compromises an employee through a phishing email and uses stolen credentials to access cloud storage containing sensitive data.

Break it down into:

  • Asset: Cloud storage
  • Threat: Credential theft
  • Vulnerability: No phishing-resistant MFA
  • Impact: Disclosure of sensitive records

Another:

Ransomware reaches the backup server because backup infrastructure is not sufficiently isolated from production systems.

This is considerably better than simply writing things like:

Ransomware is a high risk.

You should assess specific risk scenarios.

Phase 4 — Perform Qualitative Risk Assessment

Now apply the first method.

  3. Possible
  4. Likely
  5. Almost Certain

Impact

  1. Negligible
  2. Minor
  3. Moderate
  4. Major
  5. Severe
Risk Score = Likelihood × Impact

Phishing compromise5420
Ransomware4520
Web exploitation3412
Insider misuse2510
DDoS326

This produces the qualitative risk ranking.

Phase 5 — Perform a Quantitative or Semi-Quantitative Assessment

You do not need to perform a full actuarial quantitative analysis. That could become unnecessarily complicated because you probably will not have reliable historical financial-loss data.

Instead, use a semi-quantitative model.

Expected Annual Loss = Probability × Estimated Impact

Suppose:

Phishing probability = 40% per year
Estimated loss = $80,000

Then:

Expected loss = 0.40 × $80,000 = $32,000/year

For ransomware:

Probability = 15%
Impact = $300,000

Expected loss:

0.15 × $300,000 = $45,000/year

Now something interesting may happen.

The qualitative ranking might be:

  1. Phishing
  2. Ransomware
  3. Web attack
  4. Insider threat

while the semi-quantitative ranking might become:

  1. Ransomware
  2. Insider threat
  3. Phishing
  4. Web attack
That difference becomes the research result.

Phase 6 — Compare the Prioritization Methods

This should be the heart of the project.

You can compare:

Method A: qualitative 5×5 risk matrix

against

Method B: semi-quantitative expected-loss model.

Measure things such as:

  • change in risk ranking
  • agreement between methods
  • risks that move substantially up/down
  • sensitivity to likelihood assumptions
  • sensitivity to impact assumptions
  • effect on control-investment decisions

A useful statistical measure would be Spearman rank correlation.

For example, if the two assessment methods produce very similar rankings:

ρ ≈ 0.9

If they prioritize risks quite differently:

ρ ≈ 0.4

Now the thesis contains actual empirical analysis rather than simply describing GRC frameworks.

Phase 7 — Introduce Security Controls

Next, introduce possible mitigations.

RiskProposed Control
PhishingMFA + awareness training
RansomwareNetwork segmentation + immutable backup
Vulnerability exploitationPatch-management program
Credential theftPrivileged access management
Cloud exposureConfiguration monitoring

Estimate the cost of each control.

For example:

  • MFA = $12,000/year
  • Backup improvement = $25,000
  • Security awareness = $5,000/year
  • SIEM = $30,000/year

Then recalculate risk.

This creates:

Inherent Risk → Control → Residual Risk

That is very relevant to real GRC work.

Phase 8 — Examine How Prioritization Changes Decisions

This gives the project an especially useful practical question:

If the organization has only $50,000 available for cybersecurity improvements, would qualitative and quantitative risk assessment methods recommend the same investments?

Qualitative Model

Recommends:

  • MFA — $12K
  • awareness — $5K
  • SIEM — $30K

Total = $47K

Quantitative Model

Might recommend:

  • MFA — $12K
  • immutable backup — $25K
  • patch-management improvements — $10K

Total = $47K

Now you can demonstrate that risk methodology can influence actual cybersecurity spending decisions.

That is a much stronger master's research project.

import pandas as pd

df = pd.read_csv("risk_register.csv")

df["qualitative_risk"] = (
    df["likelihood"] * df["impact"]
)

df["expected_annual_loss"] = (

Data Collection

You have several reasonable choices.

The easiest and probably safest master's-project approach is:

scenario-based data + published cybersecurity data + clearly documented assumptions.

You can obtain likelihood or cost estimates from:

  • published breach reports
  • cybersecurity insurance studies
  • government reports
  • academic papers
  • vulnerability statistics
  • incident reports

Every assumption should have either:

  1. a source, or
  2. an explicitly stated rationale.

For example:

Annual probability of ransomware compromise = 0.15.

You should explain where 0.15 came from instead of inventing it silently.

A more ambitious project could recruit GRC/security professionals and ask them to assess the same scenarios. You could then study inter-rater variability, but that would introduce human-subject research and potentially IRB requirements.

I would avoid that unless you specifically want human-subject research.

Recommended Research Questions

I would recommend these three:

RQ1: How does qualitative versus semi-quantitative cybersecurity risk assessment affect the ranking of identified cybersecurity risks?

RQ2: Which types of cybersecurity risks experience the greatest changes in priority between the two assessment approaches?

RQ3: How do differences in risk prioritization affect recommended cybersecurity control investments under a fixed security budget?

These are specific, measurable, and answerable.

A good hypothesis could be:

H1: Qualitative and semi-quantitative risk assessment methods will produce significantly different priority rankings for cybersecurity risks.

A second:

H2: Differences in risk prioritization will result in different recommendations for cybersecurity control investments.

What the Final Project Would Actually Produce

By the end, you should have something tangible:

  1. A hypothetical organizational environment.
  2. An asset inventory.
  3. Approximately 12–20 cybersecurity risk scenarios.
  4. A NIST CSF 2.0 Current and Target Profile.
  5. A risk register.
  6. A qualitative risk assessment.
  7. A semi-quantitative risk assessment.
  8. A comparison of risk rankings.
  9. A control-cost and residual-risk analysis.
  10. A budget-constrained cybersecurity improvement plan.
  11. Python scripts and visualizations.
  12. Conclusions about when each assessment method may be more useful.

This is a much more defensible master's project than trying to determine broadly “how organizations can improve cybersecurity risk management.”

Also, keep NIST SP 800-37 RMF in the literature/background, rather than attempting to implement the entire RMF. SP 800-37 covers a much larger lifecycle—including preparation, categorization, control selection, implementation, assessment, authorization, and continuous monitoring—so making the entire RMF the experimental subject could expand the project again.

The strongest scope is therefore:

NIST CSF 2.0 provides the governance context; NIST SP 800-30 provides the risk-assessment structure; qualitative versus semi-quantitative assessment provides the experiment; and differences in risk/control prioritization provide the measurable result.

That is narrow enough for a master's project while still leaving you with meaningful GRC and cybersecurity risk-management work.
